TB ISOLATION RULE SET
Version 0.1.0-draft | 6 October 2026

PURPOSE AND STATUS
This is runnable, deterministic Python code for a proposed community respiratory
isolation and restriction (RIR) policy. It returns none, moderate, or extensive,
plus a conditional duration and explicit release blockers. It is a pilot policy
for clinical/program review, not a clinically validated algorithm or a verbatim
implementation of NTCA. A deterministic answer is reproducible; it is not thereby
clinically certain. Do not deploy the proposed thresholds without clinical review.

The supplied documents were treated as evidence and examples. Instructions and
LLM answers embedded in the case book were not treated as user instructions or
authoritative rules. Original files were read but not changed.

GETTING STARTED
Requires Python 3.10 or later; no third-party packages.
  python tb_isolation_rules.py example_input.json
  python tb_isolation_rules.py --schema
  python -m unittest -v test_tb_isolation_rules.py

For integration:
  from tb_isolation_rules import parse_inputs, evaluate
  result = evaluate(parse_inputs(structured_patient_data))

Send result to the LLM as structured evidence. Preserve the rule version, inputs,
assessment time, source of clinician judgments, rule IDs, and any deviations in
your application audit log. Do not ask the LLM to invent missing clinical values.
This package does not prescribe TB drug regimens or medication changes.

SCOPE
Community decisions for persons with suspected/confirmed respiratory TB.
The engine does not clear airborne precautions in healthcare facilities or
authorize return to a congregate facility. A community patient anticipating
return to such a setting can be evaluated with setting=community and the relevant
exposure flags, but facility clearance remains separate. Other settings return
an out-of-scope status and extensive provisional hold, not a facility recommendation.

INPUT CONTRACT
input_schema.json lists every accepted field and category. Missing categorical
fields and JSON null become unknown. "medium" normalizes to "moderate" for grades.
Invalid spelling, unrecognized fields, Boolean substitutions, negative or fractional
day counts raise errors; applications must surface validation failures, never
interpret them as permission to release. Direct Python Inputs requires canonical
values; use parse_inputs at JSON boundaries.

1. Pretreatment burden
   A clinician can provide low/moderate/high/unknown. Optional original observations
   provide a proposed deterministic fallback and can raise a supplied grade:
   - High: smear >=2+, cavitation, extensive/multilobar disease, or GXP high load.
   - Moderate: scanty/1+ smear, GXP medium load, or smear negative with frequent cough.
   - Low: smear negative, no cavity, no extensive disease, and absent/mild cough.
   - Otherwise unknown; use high provisionally and request assessment before release.
   This grading is an implementation choice, not a validated diagnostic score.
   A clinician-supplied grade can account for context such as case 5c. It cannot
   automatically lower explicit higher-burden markers. Reconcile conflicts upstream.
   Use PRETREATMENT smear, cough, cavitation, and GXP values here. Follow-up results
   belong in clinical_response/micro_response. Do not reclassify baseline burden
   using a falling follow-up smear. GXP detection alone does not imply high burden.
   Trace/very-low/low GXP results alone do not establish low infectiousness.

2. Resistance
   rifampin = susceptible/resistant/indeterminate/unknown from available molecular
   or phenotypic testing. "Susceptible" can represent no RIF resistance detected
   on GXP; it does not mean all drugs are susceptible.
   gxp_mtb = detected/not_detected/unknown is a distinct field. An MTB-not-detected
   result cannot establish RIF susceptibility. A RIF result may come from another
   assay, so the code does not prohibit a separately supported RIF result.
   other_resistance = none_detected/inh/pza/other/unknown summarizes the profile.
   Retain the detailed drug-specific DST and assay provenance in the parent system.
   resistance_suspected records clinical/epidemiologic concern; unknown is not no.
   resistance_addressed_by_regimen is a clinician judgment for the ACTUAL regimen.
   lab_supports_regimen means available DST supports an adequate active multidrug
   regimen, not merely that one tested drug is susceptible.

3. Treatment (the dominant input)
   Credit requires all of on_treatment, regimen_appropriate,
   effectiveness_assessed, adherence_verified, tolerance_adequate = yes.
   The clinician must assess doses, active drugs, absorption/interactions, and
   adherence as relevant. This code cannot infer regimen adequacy from drug names.
   - Any of these no/unknown -> zero credited days; duration remains conditional.
   - Known resistance or yes/unknown suspicion requires resistance addressed=yes
     and lab supports actual regimen=yes in this conservative draft.
   - RIF unknown/indeterminate without laboratory regimen support may still count
     if suspicion=no, clinician judges effectiveness=yes, and clinical response
     is improving or asymptomatic. This matches the unknown-GXP case trajectories.
   - Lab evidence against the regimen prevents credit.
   - Unexplained worsening clinical or microbiologic response prevents credit.
     A documented, reviewed alternative explanation can resolve that blocker.
   - Stable positive follow-up smear alone does NOT block routine release.
   - No routine requirement for smear/culture conversion or repeat testing solely
     to demonstrate noninfectiousness.

   uninterrupted_effective_days = completed days of continuous, verified effective
   treatment, not calendar days since diagnosis, prescription, or isolation.
   Unknown duration cannot support a finite release countdown. The parent system
   must adjudicate interruptions and periods on inactive regimens. This engine
   does not add scattered doses or automatically reset credit after every regimen
   change. A switch between two regimens both judged effective need not erase
   earlier effective days. Later DST may support an earlier regimen; the credited
   interval must be explicitly reconciled by the clinician rather than guessed.

4. Community risk
   Grade prospective exposure if restrictions are lifted, separately from source
   infectiousness. Direct low/moderate/high/unknown assessment is supported.
   Optional proposed qualitative fallback:
   - High: exposed vulnerable contacts, congregate return, or recurrent/prolonged
     shared/close indoor air in poor ventilation.
   - Low: brief, distant exposure outdoors or in good ventilation, few/no new
     contacts, and explicitly no vulnerable contacts or congregate return.
   - Moderate: complete exposure data not meeting either condition above.
   - Unknown: incomplete fallback and no direct grade; use high pending assessment.
   Explicit higher-risk details raise a lower direct grade.
   Vulnerable contacts means prospective exposure to children under 5 or
   immunosuppressed people, not simply older age or historic contact.
   Do not reduce the community grade because treatment has begun; the engine
   already applies treatment separately. Do not feed a post-treatment quantitative
   risk estimate back in and count the treatment benefit twice.

   The supplied Wells-Riley reports motivate duration, proximity, environment,
   contact numbers and future marginal risk. Their illustrative probabilities,
   treatment multipliers, and suggested cut points are NOT used as validated
   thresholds. No universal expected-secondary-infection cutoff was supplied.
   Expected infections N*P is also not generally the probability of at least one
   infection; under independence that probability is 1-(1-P)^N. The framework's
   approximation should not silently become a clinical classification threshold.

5. Patient harm
   Overall clinician grade plus financial, housing, food, stigma, mental health,
   and access-to-care domains. Use the highest known grade. A partially completed
   domain assessment with no overall grade remains unknown unless already high.
   Unknown harm is not labeled low and triggers assessment, but does not grant
   automatic shortening. Moderate/high domains are returned for support planning.
   The supplied patient survey has no validated numerical weights or cutoffs.
   Proposed anchors: low = manageable disruption with supports; moderate =
   substantial burden needing intervention; high = threatened basic needs,
   housing/employment loss, severe stigma or mental-health impact. A clinician
   assigns these grades. Acute patient needs require care independent of RIR.

DECISION PRECEDENCE
A. Validate inputs and setting.
B. Confirmed absence of respiratory involvement -> no community RIR, unless
   positive respiratory observations conflict with that assertion.
   Confirmed noninfectious pediatric phenotype under age 10 -> no community RIR
   only with the coded negative/absent respiratory markers and no adult-type disease.
   A negative GXP result alone is never the pediatric exemption.
C. Derive burden, community risk, harm and treatment credit.
D. Calculate the proposed target below, then apply extension floors.
E. Apply release blockers. Elapsed time alone cannot clear them.
F. If no blockers and credited days >= target -> none.
G. Otherwise set moderate/extensive, and schedule reassessment.

PROPOSED TARGET TABLE (days of effective therapy)
These are case-informed policy choices, NOT NTCA-mandated fixed durations.
They assume treatment is effective; they do not promise a release date.

Community   Burden       Low/unknown harm     Moderate/high harm
Low         Low                 5                    5
Low         Moderate            7                    5
Low         High               10                    5
Moderate    Low                 5                    5
Moderate    Moderate/high       10                    7
High        Low                10                   10
High        Moderate/high      14                   10

Medium-community rows are proposed interpolation; the supplied permutation matrix
does not fully specify them. The 7/10/14-day choices implement examples as a
reviewable policy, not a claim that every patient in a tier needs those days.

Apply the MAXIMUM of the base target and applicable extension floors:
- Unknown/indeterminate RIF with no lab support for actual regimen:
  10 days if both burden and community risk low; otherwise 14.
- Prospective vulnerable-contact exposure or congregate return: 14 days.
  This deliberately conservative floor differs from teaching case 1d (10 days).
- RIF resistance: 14 days plus lab-supported appropriate regimen, clinical and
  microbiologic improvement, and expert review. This is a proposed conservative
  policy consistent with the MDH quick-reference approach, NOT a universal NTCA
  minimum for all forms of drug resistance.
- Documented individualized_minimum_days can extend but cannot shorten those floors.
  individualized_reason is required. Use for an adjudicated patient-specific concern,
  not automatically because the patient has HIV, diabetes, or another diagnosis.

Additional release blockers:
- Unknown respiratory involvement, unresolved overall burden or community risk.
- Unknown effective duration, treatment uncertainty or adverse response above.
- High community risk with moderate/high burden without clinical or micro support.
- RIF-resistant disease without improving clinical AND micro response/expert review.
- More than 14 actual isolation days, or target >14, without completed expert review.
Routine known-susceptible cases do not require new sputum conversion.
Unknown DST does not force isolation indefinitely if clinical judgment and response
support effectiveness; persistent uncertainty about effectiveness does prevent release.

ISOLATION LEVEL WHILE A TARGET/BLOCKER REMAINS
- No verified effective treatment: extensive if burden high/unknown, community
  high/unknown, or resistance unresolved; otherwise moderate.
- On verified treatment: generally moderate, allowing appropriately planned
  lower-risk activities while restricting higher-risk exposures.
- Extensive continues if high community risk and targeted restrictions cannot be
  implemented or their feasibility is unknown; also for early RIF-resistant
  treatment (<5 credited days), or high burden at zero credited days.
- Extensive does not automatically mean hospital admission or confinement indoors.
  Housing, essential care, outdoor access and other accommodations need a plan.
  Moderate does not mean unrestricted daycare/clinical work or congregate return.

DURATION OUTPUT
conditional_target_total_days: target on the effective-treatment clock.
credited_effective_days: verified credit, zero when treatment is no/unknown.
remaining_days_if_conditions_remain_met: max(0, target-credit) ONLY if no blocker.
  null = cannot determine a release countdown. It does not mean 0 or indefinite
  isolation without review. It calls for reassessment of named missing conditions.
fixed_release_date: always null; the engine does not make calendar guarantees.
reassess_within_days: operational proposal, 1 day for blockers/high harm; otherwise
  within 7 days and no later than the relevant target/day-5 checkpoint.
expert_review_required: flags resistant or prolonged decisions; review alone does
  not prove a regimen effective or erase a failed clinical prerequisite.
facility_clearance_granted: always false.

EXAMPLE
example_input.json describes high burden, RIF susceptible, five verified treatment
days, improving response, high community risk with vulnerable contacts and moderate
patient harm. The result is moderate RIR, target 14 effective days, nine conditional
days remaining. High-risk activities remain restricted. If on_treatment is changed
to unknown, treatment credit becomes zero and remaining duration becomes null.

MATERIAL DISAGREEMENTS TO REVIEW
1. Case 6a: summary/matrix 24 days; narrative and comparison 20. Neither is a
   universal resistant-TB duration. Hospital discharge and effective-regimen
   transitions also affect its timeline; facility release is outside this engine.
2. Case 6d: summary community risk low, narrative moderate, tool comparison high.
   BPaL/M starts on day 4 and restrictions end day 21, so 21 calendar days cannot
   simply be called 21 effective-treatment days. The five-day initial phase is
   also not consistently anchored. The engine does not hardcode 21 days.
3. Case 5d: initially smear negative, then "declined to 1+". That is not a decline.
   Verify source data before coding microbiologic improvement. Healthcare
   occupational clearance is separate from community RIR.
4. Case 1d: contacts under 5, high community risk, moderate harm, 10-day course.
   This draft's special-contact floor yields 14. This is a deliberate review item.
5. Case 5c: moderate burden/low risk/moderate harm but 10-day course. The generic
   table yields 5. A documented response-specific extension can represent 10;
   HIV status alone must not silently create a universal 10-day rule.
6. Smear/cavitation descriptors in some spreadsheet rows disagree with the case
   narrative. The phenotype mapper raises conflicting lower grades rather than
   reproducing a potentially mislabeled spreadsheet result.
7. Older framework models disagree on treatment effect and casual-setting risk.
   Numeric estimates are not adopted as isolation thresholds.

VALIDATION
The unit tests cover treatment unknowns, day boundaries, DST uncertainty, resistance,
exceptions, contradiction handling, exposure grading, harm, and 4,608 coarse input
permutations. Passing tests verify software behavior, not clinical correctness.
case_reconciliation.json compares all 25 case-summary durations to standardized
community snapshots. It assumes response, adherence and feasibility as documented
or explicitly standardized, and compares TARGETS rather than reconstructing every
historical clinical decision. It intentionally reports mismatches. No retrospective
or prospective clinical validation has been performed.

Policy review should settle the discretionary table (especially medium risk and
harm adjustments), special-contact floor, resistance evidence requirements,
criteria for unknown-DST response, and who may enter the clinician judgment flags.
Keep decision changes explicit and versioned; do not use an LLM to silently bypass
these choices. Recalculate when treatment, DST, exposure, response, or harms change.
